## Draft

How many SQLs does the account produce in a week right now? I ask because that number decides whether bidding toward SQLs is possible yet. Meta wants roughly 50 optimization events per ad set per week to exit learning, and most B2B software accounts sit well under that on SQLs. So an "optimize to pipeline" setup sits in learning and spend drifts back toward whoever converts cheapest.

The approach that avoids that trap is a ladder, not a jump. Optimize to the deepest stage that clears the volume bar, send every later stage back through the Conversions API with the CRM stage and deal value attached, then move the optimization event down the funnel as volume allows. One detail that catches teams: Meta's CRM-based conversion leads goal only works with Instant Forms, so if demos come through a website form, the stage feedback has to be built server-side.

On B2B software specifically, I ran the Meta side of an account selling to home service contractors, where the buyer was a trade owner, not an interest. Meta's job was creating demand for a category those owners didn't know existed, and search captured it. That window also followed a seed round, so the credit is shared, but over six months inbound leads and ARR both doubled. To be straight about scale: that account spent a few thousand a month per platform, well below the budgets where CAC starts to bend, and the CRM feedback build would be done with the tracking specialist I work with, who handles browser and server-side tagging.

I built and sold my own e-commerce business, and owning that P&L is why I judge a channel on payback rather than on what Ads Manager reports.
